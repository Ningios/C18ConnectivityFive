# CC18 beta6 original power backend restoration

The replacement power backend inherited the original provider's absolute command paths but removed its original callbacks and RootHide patch entry. Path-only conversion did not resolve the actual on-device failure; the precise callback or privilege failure in the replacement remains unproven. The original provider previously spawned a respring command on this device, so this revision restores that execution path instead of extending the replacement.

The first replacement removed the original C18PowerMenu.dylib, its injection plist, and the RootHide AutoPatches marker. Its independent UIAction/spawn implementation broke the original execution chain. The subsequent path-only rebuild did not restore functionality on device. A read-only record of the original provider on this same device shows one respring request followed by a successfully spawned killall; this does not prove that every power operation succeeded.

This revision retains the exact original provider and plist in both baselines and its original RootHide patch symlink in arm64e. The companion reverts to the historical bridge: invoke the original `_powerTriggered`, capture its five original UIAlertAction handlers, and forward selections from the context menu to those handlers. If capture cannot be established, present the original alert instead. The companion no longer runs its own power command path; the obsolete standalone path helper and its test remain in the repository as non-production historical material.

Local checks validate the original provider's exact hashes and package entries, the historical bridge's exact source hash, and arm64/arm64e syntax without running power commands. The manual CI signs the companion and verifies four primary programs extracted from each final deb using macOS codesign --verify --strict --all-architectures; it also checks that original provider files and the RootHide symlink survive packaging.

The first build (run 43713757934, commit 0229e2d) compiled and packaged both versions, then failed final macOS validation on the old ordinary-rootless ControlCenter18 core's Designated Requirement. The pinned core and module signatures include former certificate requirements. The follow-up renews their ad-hoc signatures while preserving identifier, entitlements, flags and every runtime section's address, length, type and bytes; it keeps the final strict signature check. The power implementation is unchanged by this signing repair. That failed build uploaded no artifacts.

This repair does not prove device execution. Successful spawn alone does not establish tool exit success or permission to complete a reboot. The original safe-mode implementation writes `.C18SafeMode` then requests a respring; its consumption by the jailbreak framework is not established here. No automatic installation, injection, respring or source publication is part of this repair. Version stays 3.0-beta6 per the user's existing requirement; distinguish artifacts by commit, run and SHA256.
